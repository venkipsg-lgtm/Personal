RAG Pipeline

From knowledge to grounded answer

A production RAG system involves two phases: Indexing your knowledge and retrieving relevant information when a user asks a question.

What each component really does

01 / KNOWLEDGE

Documents are not automatically searchable

PDFs, web pages, databases and transcripts first need their useful text and metadata extracted.

02 / CHUNKS

Large documents are divided

Smaller chunks make retrieval more precise. Chunk size and overlap strongly influence RAG quality.

03 / EMBEDDINGS

Meaning becomes numbers

An embedding model transforms each chunk into a numeric vector that represents its semantic meaning.

04 / VECTOR DATABASE

Vectors are indexed

Vector databases efficiently locate chunks whose embeddings are closest to the user's query embedding.

05 / RETRIEVAL

Top-K candidates are found

Similarity search returns the chunks most semantically related to the user's question.

06 / RERANKING

Best candidates can be reordered

A reranker can evaluate the query and candidate chunks more carefully before sending context to the LLM.

07 / AUGMENTATION

Retrieved knowledge enters the prompt

The user's question and selected chunks are combined into a prompt instructing the LLM to use the supplied evidence.

08 / GENERATION

The LLM produces the answer

The language model reasons over its instructions, user question and retrieved context to produce a grounded response.

IMPORTANT

RAG doesn't retrain the LLM

Your documents usually remain outside the model. Relevant knowledge is retrieved dynamically and inserted into the context window.
